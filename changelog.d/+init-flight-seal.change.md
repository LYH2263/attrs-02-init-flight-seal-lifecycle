Added a formal construction-flight lifecycle. `attr.get_init_phase(instance)` reports the current phase as a member of the new `attr.InitPhase` enum — `pre_init`, `assigning`, `validating`, `post_init`, `ready`, or `aborted` — and `attr.get_init_field(instance)` returns the storage name of the field currently being planned-assigned (only to the constructing thread). While a generated `__init__`/`__attrs_init__` is assigning and validating fields, `Converter(takes_self=True)`, `Factory(takes_self=True)` and validators can no longer rewrite an already assigned attribute storage name (new `attr.SealedAttributeError`), nor pre-write a name that has not been assigned yet (new `attr.UnassignedAttributeError`, both subclasses of the new `attr.InitFlightError`) — whether they use `object.__setattr__` or the generated `__setattr__`. The same rules apply in `__attrs_pre_init__`; `__attrs_post_init__` keeps the previous writability (including the frozen post-init pin), and finished instances keep plain frozen/`on_setattr` semantics. `evolve`/`__replace__` re-run the whole flight on the new instance; `assoc` and `pickle`/`__setstate__` restore storage directly and yield `ready` instances. Flights are attached to the instance under construction, so concurrent constructions never share state.
